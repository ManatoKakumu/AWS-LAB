# 2026-07-16: 03-rds-scaling(Terraform実装〜レビュー〜apply確認〜振り返り、フェーズE完了)

- 種別: 実装課題(Terraform)、コードレビュー、実機確認、振り返り
- 内容:
  - `.drawio`の設計図のみを見て(READMEは見ずに)ネットワーク部分(VPC/サブネット/IGW/ルートテーブル)から実装。DB用の2サブネットを`for_each`化し、EC2用の単独サブネットとは分離する設計にできた
  - `for_each`の使いどころについて、当初「値が同じかどうか」で判断し誤った結論(サブネット・DB用NACLを分割する方向)を出したが、SGルールとの比較・ルートテーブルでの過去の判断との比較というソクラテス式の問いかけを経て、「役割が同じかどうか」という正しい判断基準に自力で到達した
  - SGを実装。CIDRでなくSG参照(`referenced_security_group_id`)を使うべきという判断を自発的に行った。ただしコピー実装時のポート番号見直し漏れ(`0`のまま残留)が複数箇所で発生し、指摘して修正
  - NACLを実装。`.id`の付け忘れ、`protocol = "ssh"`という誤ったプロトコル指定、エフェメラルポート範囲の記載漏れ、ルール番号の重複、といった構文・記述レベルのミスを順次指摘・修正。DB用NACLは、ルートテーブルでの過去の判断(単一リソース+`subnet_ids`のリストで両AZをカバー)との一貫性から、自力で「単一NACLにすべき」と判断できた
  - NACL Outboundの3306番ルールについて、メンター(Claude)が「専用ルールが必要」と誤った指摘をしたのに対し、本人が「実機ですでにフェイルオーバー・レプリケーションが正常動作している」という事実と、「1024-65535という範囲は数値として3306を含む」というポート範囲の包含関係の両方から反論し、メンター側の誤りを訂正させた
  - セッション中盤、学習のストレス・しんどさの表明があった(`02-nacl-experiment`の2026-07-14に続き2回目)。技術力の問題ではなく、細かい指摘の連続という進め方自体の精神的負荷によるものと考えられる。休憩を挟みつつ、レビュー水準は落とさない方針で継続した
  - EC2を実装。AWSコンソール構築時の記録(`mariadb105`パッケージ、`dnf`コマンド)をもとにuser_dataを修正。ブラウザ経由のSSH(EC2 Instance Connect)が`key_name`なしで機能する仕組みも対話を通じて理解した
  - RDS(プライマリMulti-AZ + リードレプリカMulti-AZ)を初めて実装。構文はメンターが最小サンプルを提示し、値は本人の設計に合わせて記述。レビューで`backup_retention_period`の指定漏れ(MySQL/MariaDBのリードレプリカ作成にはソース側で自動バックアップ有効化が必須という制約)を発見し、修正
  - `terraform apply`を実施し、AWS CLI(閲覧専用IAMユーザー)でプライマリ・リードレプリカの設定(Multi-AZ有効、暗号化有効、エンドポイント)、EC2、VPC/サブネット構成を確認。すべて設計通りで余計なリソースもなかった
  - 実験手順(EC2からのmysql接続、レプリケーション確認、手動フェイルオーバー)を提示し、本人が実施。`terraform destroy`を待つ間にフェーズE(振り返り)を実施
- 発見:

  - 一方で、メンターの誤った指摘に対して事実と論理の両方で反論し、実際に訂正させるという新しい強みが明確に見えた回だった。`02-nacl-experiment`で見られた「根拠を自分で吟味する姿勢」が、より高度な形(数値的な包含関係の理解+実機検証)で発展している
  - コンソール構築(フェーズC)とTerraform実装(フェーズD)でデフォルト値が異なる罠(RDSのバックアップ保持期間)を、レビューで事前に発見できた
