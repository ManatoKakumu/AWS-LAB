# 2026-07-13: 02-nacl-experiment 設計レビュー

- 種別: 設計課題(実験設計)のレビュー
- 内容: `02-nacl-experiment`の検証シナリオを4ラウンドにわたってレビュー。以下の誤りを順に修正させた
  1. 検証プロトコルにICMP(ping)を選定しており、ポート概念自体を持たないICMPではエフェメラルポートの検証が成立しないことに気づかせ、curl/HTTPへ変更
  2. 「壊す→直す」のうち「直す」ステップが検証シナリオから欠落していたため追加
  3. SGとの対比実験が、デフォルトの全許可Outboundルールを残したままでは何も証明できない設計になっていたため、Outboundルールそのものを削除して検証する方式に修正
  4. SGのOutboundを「Deny」に設定する記述があったが、SGにはAllow/Denyの選択肢自体が存在せず、ルールの削除でしか制限できないことに気づかせた(NACLとの明確な違い)
  5. ユーザーデータの`yum install`実行に必要なアウトバウンド通信と、SGルール削除のタイミング競合について検討させ、削除ステップを起動完了後に置く設計にした
  6. 「アウトバウンドルールで拒否されていても」という不正確な表現を「許可されていなくても」に修正させた
- 発見: プロトコル選定やSGのDeny概念など、実機の制約に直面するまで気づけない誤りが複数あったが、指摘後の軌道修正は速く、especially「well-knownポート境界(0-1023)を使えばOS依存のエフェメラルポート範囲を正確に調べなくても実験を組み立てられる」という改善案は自力で導けた。「SGにはDenyルールが存在しない」という気づきも、NACL/SGの目的差分混同という既知の弱点を自力で乗り越えた例
