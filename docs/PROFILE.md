# PROFILE

このリポジトリの学習者本人に関する情報。メンターが毎回の課題設計・レビューの前提として参照する。

## 最終目標

「AWSが使える人」ではなく、**どのクラウドでも本質的な設計ができるクラウドエンジニア**になること。

AWSを学習対象とするが、AWS固有の知識だけでなく、以下のようなクラウド全般で通用する設計思想を身につける。

- クラウドネイティブな設計思想
- 高可用性
- スケーラビリティ
- セキュリティ
- 可観測性
- Infrastructure as Code
- 運用性
- 保守性
- コスト最適化

Terraformなどのインフラ管理も、実務レベルまで習得する。

## 経歴・現在地

- Web/アプリ開発エンジニア。フロントエンド・バックエンドの実務経験は1年
- 自分でコードを書く経験は薄い。AI(Claude等)が生成したコードを読む機会はあるが、自力で書く機会は少ない
- AWSハンズオン経験: EC2/VPCなどネットワーク基礎、IAM/セキュリティ関連、RDS/DynamoDBなどDB、Lambda/サーバーレス。ただし本人いわく「手順通りに進める写経」に近く、理解度は着手当初は未検証だった → 2026-07-11に初回評価済み(詳細は[CURRENT_LEVEL.md](CURRENT_LEVEL.md))
- IaC(Terraform)経験: 開始時点でほぼゼロ。CLIはローカルにインストール済み、過去に`terraform apply`でEC2を起動した記憶がある程度
- AWSアカウント: 自分のクレジットカードで作成した個人アカウントを保有

## 学習環境

- OS: Windows。シェルはPowerShellとGit Bash(POSIX)の両方が使える
- Terraform CLI: ローカルにインストール済み(バージョン未確認 → 最初のTerraform課題着手時に `terraform version` で確認しCURRENT_LEVELに記録する)
- AWSアカウント: 自分のクレジットカードで作成した個人アカウント
- 既定リージョン: ap-northeast-1(東京)。特にこだわりはないため、変更したい場合は本人から申告する
- 予算感: 学習用AWS費用は月あたり数千円程度まで許容
- apply方針: **コードレビュー中心で進める。** Terraformはほぼ未経験で構文自体に不慣れなため、`terraform plan`(課金なし)まではセットで毎回実施し、実際の`apply`は本人の理解度に応じて要所要所のみ行う。applyした場合は確認後に必ず`destroy`する。詳細は[MENTOR_RULES.md](MENTOR_RULES.md)のガードレール参照

## 学習の進め方(本人の希望)

1. メンター(Claude)が学習者のレベルに合った実務課題を出す
2. 学習者が自力で設計・構築する(AIやネット検索に頼らず、まず自分の頭で考える)
3. メンターが完成後に厳しくレビューする
4. 改善点を提示する
5. 次のお題を決める

このサイクルを長期間継続する。理解できるようになった内容は徐々に課題から外し、苦手な分野は重点的に出題する。
